# Clinical covariance and ΦID workflows

The covariance sensitivity excludes normative dyad 5 from covariance estimation and retains the original downstream EEG sample. The separate-cohort tonic driver fits the normative models and compares them with the preserved clinical fits.

The four main ΦID contrasts and the response-period × condition interaction have separate target inventories. Each control workflow applies trial shuffling, a directional gate for time shifts and geometry-specific tier assignment. The resulting 51 main and seven interaction Tier A/B targets define the starting inventories for the sensitivity analyses. Eligibility depends on the analysis. The chronological-half comparison uses one Holm family across its eleven eligible targets and reports the interaction separately.

Run computations in an isolated working tree containing the authorized source manifests, trial and block mappings, input files, verified upstream outputs and matching software versions. The archived drivers expect their original sibling-directory layout. The candidate source distribution alone cannot reconstruct these inputs or historical hash receipts. Preserve the original receipts and use separately documented input and source bindings when relocating a run.

The supplementary-table builder consumes saved results. ST12 reports the primary tiers, ST13 the role-order comparison, ST14 the lag offsets, ST15 the history assessment and ST16 the signal-timescale diagnostics. For this builder supply the results root in TETRADIC_RESULTS_ROOT and a new output directory in TETRADIC_TABLE_OUTPUT. It writes separate main and interaction CSV tables. For covariance, TETRADIC_CLINICAL_ROOT and TETRADIC_TONIC_ROOT locate the private clinical project and tonic analysis roots. The signal-diagnostic reference functions are included under phiid/.


## Dependency locations

Extract a fresh copy of the complete clinical tree into a private writable run directory. Keep the dated workflow folders as siblings. Drivers still place new records and checkpoints beside their release copies. Never run from the reference archive. Several drivers read prepared files during module initialization.

* Set `TETRADIC_NORMATIVE_REFERENCE_ROOT` to the bundled `clinical-dyads/normative-references` directory for the public references. The matched per-map folder supplies the public specification, map inventory and sign assignments. The main and interaction control folders supply reference scripts, public specifications and group-level target inventories. The signal-timescale and role-swap folders supply reference scripts used when freezing clinical sensitivity targets.
* Two historical checks require an authorized private reference tree. The matched per-map preflight reads `PhiID_Matched_PerMap_2026-10-26/Leader_minus_Follower_Mirroring.npy` for a numerical comparison. Interaction selection and finalization hash `PhiID_Normative_Interaction_Controls_2026-10-26/directional_tiers.json` to check preservation. Use the recorded reference versions when comparing historical hashes. Executing the normative sensitivity scripts themselves additionally requires the original normative roster, inputs and upstream records.
* For covariance supply TETRADIC_CLINICAL_ROOT, TETRADIC_PHASIC_ROOT and TETRADIC_TONIC_ROOT for the same study tree. Set TETRADIC_SUBJECTS_DIR to the MNE subjects directory containing fsaverage. The workflow loads the phasic and tonic engine scripts from the release. The prepared EEG, forward and inverse inputs, parcellation, model checkpoints and runtime overlay remain external.
* Supply the prepared clinical manifests, tiles, signs, targets and prerequisite verification records in the workflow directories used by each stage. For table generation set TETRADIC_RESULTS_ROOT and TETRADIC_TABLE_OUTPUT. The saved-results verifier uses TETRADIC_RESULTS_ROOT and a separate, new TETRADIC_VERIFICATION_OUTPUT directory.
* The release retains historical receipt names, Boolean fields, lock names and the explicit full-run flag because the drivers check them. Existing signed or hashed paths inside private specifications remain binding. A release copy has a different hash when paths or log messages change. Keep original receipts immutable. A run using release copies needs its own provenance chain, including upstream specifications or benchmarks wherever required. Cache and checkpoint identities cannot be transferred by editing digest values.
